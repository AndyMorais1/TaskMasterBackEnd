<h2> Introdução </h2>

<p> O projeto consiste na implementação de uma aplicação mobile para gerenciamento de tarefas, que tem como objetivo proporcionar  aos usuários uma maior organização e um aumento significativo da produtividade dos mesmos. </p>

<h2>  Nome e Proposta Inicial do Projeto</h2>

<p>  O Task Master é um sistema de gerenciamento de tarefas criado exclusivamente para usuários que desejam gerenciar melhor as suas tarefas, proporcionando assim um aumento na produtividade. O Task Master permite a criação e o gerenciamento de tarefas individuais, fornece estatísticas sobre as tarefas executadas e possui a função pomodoro.</p>

<h2>Enquadramento </h2>

<h2>Guiões</h2>

<h3>Criar uma lista</h3>

<p>A nossa aplicação dá a possibilidade de criar listas para organização de tarefas.</p>

<h4>Passo:</h4>

<ul>
  <li>Abrir o menu lateral;</li>
  <li>Clicar no botão de criar listas;</li>
  <li>Definir o nome da lista;</li>
  <li>Clicar em confirmar.</li>
</ul>


<h3>Criar uma tarefa</h3>

<p>A hierarquia do nosso aplicativo sugere que toda tarefa está vinculada a uma lista, logo, não existem tarefas sem listas.</p>

<h4>Passos:</h4>

<ul>
  <li>Clicar no botão de criar tarefa ( que se encontra no canto inferior direito das telas principais );</li>
  <li>Adicionar o nome da tarefa;</li>
  <li>Selecionar a lista a qual a tarefa pertencerá;</li>
  <li>Escolher a data de entrega da tarefa;</li>
  <li>Adicionar a hora de entrega da tarefa;</li>
  <li>Clicar em confirmar.</li>
</ul>


<h3>Usar o Pomodoro</h3>

<p>O pomodoro é um cronómetro da aplicação, que permite a utilização da técnica de foco com o mesmo nome.</p>


<h4>Passos:</h4>

<ul>
  <li>Selecionar tela de pomodoro;</li>
  <li>Escolher entre a opção "iniciar" e "pausar";</li>
</ul>

<h4>Passos:</h4>

<ul>
  <li>Abrir o menu lateral;</li>
  <li>Clicar em estatísticas.</li>
  <li>Selecionar período de avaliação (dia, mês ou ano)</li>
  
</ul>

<p>O primeiro caso de uso se resume a criação de uma lista “ Banco de dados”, que será uma lista para guardar tarefas relacionadas a estudar sobre banco de dados, e nesta lista serão adicionadas duas tarefas, “Instalar MySQL” e “Criar o primeiro Banco de dados”, a primeira tarefa ( Instalar MySQL), será agendada para o dia “19/01/2025” às “18h30min”. <h2>Componentes principais </h2>

<ul>
  <li>Frontend (Interface do usuário)</li>
  <li>Backend (Servidor e lógica da app) </li>
  <li>Banco de dados (Armazenamento de tarefas). </li>
</ul>
  
 
<h3>Frontend </h3>

<p> O frontend da app será construído utilizando o Android Studio, utilizando como linguagem o 
Kotlin e o framework de auxílio será o JetPack Compose. A interface do usuário permitirá ao 
mesmo gerenciar as listas de tarefas, tarefas, utilizar o pomodoro e visualizar as estatísticas relacionadas às tarefas. </p>

<h3>Backend </h3>

<p>A parte backend, que está relacionada as APIs e ao Servidor, será feito com Java, utilizando o 
framework Spring Boot. Além das APIs e do servidor, serão também criadas com o Spring Boot 
as conexões entre o frontend e o servidor, e entre o servidor e o banco de dados, com a 
implementação de APIs Restful. O backend será o responsável por processar as requisições do 
frontend e gerenciar as operações com as tarefas. Ele será implementado como uma API simples. </p>

<h3>Banco de dados </h3>

<p>O banco de dados será implementado com MySQL, usando a linguaguem SQL, e terá a implementação de diversos mecanismos de proteção de dados que virão da parte do Spring Boot. O banco de dados será responsável por armazenar as informações das tarefas e dos usuários. Cada tarefa terá campos como título, data de vencimento e prioridade.</p>

<h2>Fluxo de dados</h2>


<h3>Criação de Tarefa: </h3>

<ul>
  <li>O usuário insere os detalhes da tarefa no frontend (título, lista associada, data de entrega, hora de entrega, prioridade). </li>
  <li>O frontend faz uma requisição POST para o backend. </li>
  <li>O backend salva a tarefa no banco de dados. </li>
  
</ul>

<h3>Listagem de Tarefas:</h3>

<ul>
  <li>O frontend solicita ao backend a lista de tarefas via uma requisição GET. </li>
  <li>O backend recupera as tarefas do banco de dados e retorna para o frontend exibi-las. </li>
 
</ul>

<h3>Edição de Tarefa:</h3>
 
 <ul>
  <li>O usuário seleciona uma tarefa para edição. </li>
  <li>O frontend envia uma requisição PUT com os novos dados.</li>
  <li>O backend atualiza a tarefa no banco de dados. </li>

 </ul>

 <h3>Exclusão de Tarefa: </h3>

 <ul>
  <li>O usuário seleciona uma tarefa para exclusão. </li>
  <li>O frontend envia uma requisição DELETE.</li>
  <li>O backend remove a tarefa do banco de dados. </li>
  
 </ul>


<p>Essa arquitetura é simples, mais eficiente para um aplicativo de gerenciamento de tarefas. É 
escalável, permitindo a adição de funcionalidades como autenticação de usuários ou envio de 
notificações no futuro. Para este projeto semestral, ela oferece uma base sólida com o foco em 
CRUD de tarefas, utilizando tecnologias acessíveis e amplamente suportadas.</p>

<h2>Conclusão  </h2>

<p> O Task master é um aplicativo de gerenciamento de tarefas, que permite a criação e gerenciamento de tarefas individuais, fornece estatísticas sobre as tarefas executadas e um sistema de foco pomodoro.</p>

<p>Tem como objetivos fornecer uma experiência de usuário simples e direta ao ponto, permitindo que sempre que o usuário entrar na aplicação ele esteja focado nas tarefas que precisa acessar, criar ou editar. 
Para isso nos propomos a disponibilizar uma interface simples que centraliza as tarefas, sem muitas informações a serem apresentadas de uma única vez. Almeja também ser capaz de facilitar a organização de tarefas, tendo a possibilidade de agrupar as tarefas em listas, definir prioridade e data para a entrega/realização de cada uma das tarefas. </p>
